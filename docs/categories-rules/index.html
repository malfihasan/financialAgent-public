Categories & rules¶

The category system¶

Categories are two-level: group:subcategory (e.g. housing:rent_mortgage). The canonical list lives in a reference CSV shipped with the app and is shown on the dashboard's Categories page with readable names and emojis.

The set is deliberately closed: rules, location lookup, and the LLM prompt are all tuned against it. Adding categories is highly discouraged — it fragments your history and new categories only apply going forward.

If you must add one (Dev profile only, via the Categories page):

  • The group must be one of the existing groups.
  • The subcategory is free-form; it is slugified to lower_snake_case.
  • The reference CSV and the dynamic category store are both updated.

The rule engine¶

Rules run first in the pipeline — before location lookup and the LLM — and are deterministic keyword matches against transaction descriptions.

Manage rules on the Rule Engine page:

  • Create, edit, reorder (priority), and delete rules.
  • Rules created from the dashboard are stored in rules_dynamic.json and survive app updates.
  • The rule suggester can propose rules from your uncategorized transactions.

Editing a single transaction¶

Use the edit button on any row of the Transactions page. Manual edits are recorded with the user_defined stage (orange tag) and are preserved across processing runs.
