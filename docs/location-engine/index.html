Location Engine¶

In FinAgent: Configuration Settings Location Engine for Categorization

The Location Engine turns an unclear statement description into a likely business type before FinAgent asks the AI Engine. It runs as part of processing, and most methods contact an external map service directly from your machine.

Rules -> Location Engine -> AI Engine -> Merge

Select a method in Settings -> Location Engine for Categorization. Accepted results are cached in your local processing folder, making repeat runs faster and reducing network requests.

Choose a method¶

Settings option Config value Profile Internet Direct cost Best for
Open Street Map nominatim Personal, Dev Required Free Simple, no-key lookup
Place API place_api Personal, Dev Required Google billing Maximum Google coverage
Place API combined flow place_api_combined Personal, Dev Required Google billing on fallback Fewer paid Google calls
Disabled none Personal, Dev No Free Rules and optional AI only

For most users, start with Open Street Map. Choose Place API combined flow when free results leave too many merchants unresolved. Choose Disabled when no merchant text should be sent to a map provider.

Open Street Map¶

Open Street Map uses the public Nominatim service. It requires no API key. FinAgent sends the merchant description and available location text, accepts only usable category evidence, and stores an accepted result locally.

Set it up¶

  1. Open Settings -> Location Engine for Categorization.
  2. Choose Open Street Map (free, built in).
  3. Optionally open Advanced and enable the contact-email field. Sharing an email with OpenStreetMap is voluntary and off by default.
  4. Save, then run Process.

Use this option when you want free lookup with minimal setup. Public Nominatim may rate-limit heavy usage, so keep the local cache and avoid unnecessary refreshes.

Google Places API¶

Google Places is FinAgent's higher-coverage location option. It does not require Selenium or a browser driver, but it requires a Google Cloud project with billing enabled.

Place API modes¶

  • Place API queries Google for each unresolved, uncached merchant. It offers the most direct Google coverage and usually makes the most paid requests.
  • Place API combined flow tries free OpenStreetMap first and calls Google only when OpenStreetMap has no usable category. Start here when cost matters.

Each mode keeps a separate local cache.

Create and protect an API key¶

  1. Open Google Cloud Console.
  2. Create or select a project with billing enabled.
  3. Enable Places API (New).
  4. Create an API key.
  5. Restrict the key to Places API (New) and add appropriate application restrictions for your environment.
  6. In FinAgent, open Settings -> Location Engine for Categorization.
  7. Choose Place API or Place API combined flow.
  8. Paste the key into Google Places API key, save, then run Process.

Google maintains the current walkthrough at Get a Places API key. FinAgent masks a saved key when the dashboard reads it back. Do not publish your config.json or include the key in screenshots.

How a Google match is accepted¶

For each unresolved merchant not already cached, FinAgent:

  1. Extracts a merchant query and the most specific available location hint.
  2. Sends that query directly from your machine to Google Places.
  3. Compares the returned business name with statement evidence.
  4. Requires an exact ZIP match when ZIP evidence exists, or compatible city/state evidence when that is the best available location.
  5. Maps only specific supported Google place types to a FinAgent category.
  6. Caches an accepted category for later runs.

Broad types such as store and point_of_interest are ignored because they do not identify a useful category. Errors, ambiguous names, location mismatches, and unmapped types remain unresolved instead of being guessed.

Privacy and cost¶

Google receives the merchant query and available ZIP, city, or state needed for the search. FinAgent does not include transaction amounts, account numbers, raw statement files, or your display name. Requests go directly to Google; there is no FinAgent proxy.

Google bills the Cloud project attached to your key. FinAgent adds no fee and cannot determine the final invoice. To control usage:

  • Prefer Place API combined flow.
  • Keep cached results instead of clearing them routinely.
  • Restrict and monitor the API key in Google Cloud.
  • Configure Google Cloud quotas and billing alerts.
  • Review current Places API pricing.

Disabled¶

Choose Disabled to skip the Location Engine. No merchant description is sent to OpenStreetMap or Google. Rules still run, followed by the selected AI Engine, if enabled.

How FinAgent treats every result¶

Location evidence is never permission to guess. Every resolver compares merchant and location evidence, maps only recognized business types, and leaves uncertain results uncategorized. An unresolved transaction continues to the AI Engine or remains available for manual review.

Cache controls¶

Normal runs reuse the active method's local cache. Advanced terminal runs can clear or refresh it:

finagent --clear-lookup-cache --orgs boa
finagent --refresh-lookup-cache --orgs boa

Use refresh only when a cached business is outdated or while testing a resolver; it intentionally makes new network requests. See Settings for all configuration fields and Running from the Terminal for one-run method overrides.
