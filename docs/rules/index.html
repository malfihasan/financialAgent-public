Rules¶

In FinAgent: Configuration Rule Engine

Rules are deterministic keyword checks that run first in every processing run. They are fast, repeatable, and do not require internet access.

A rule connects one or more transaction-description keywords to a category. When the evidence matches, FinAgent assigns that category and records rule as the categorization stage. Transactions without a match continue to the Location Engine, then the optional AI Engine.

Rule priority¶

Rules are evaluated by priority. More specific merchant patterns should run before broad terms so a generic keyword does not capture the transaction first. Built-in rules occupy the lower priority range; custom dashboard rules must use priority 52 or higher and may use decimals.

When two rules could match, inspect their keyword coverage and give the more specific one the earlier effective priority. Reprocess after changing rules to apply them to pipeline output.

Manage rules in the dashboard¶

Open Configuration -> Rule Engine from the header menu. You can:

  • Search and filter built-in or custom rules.
  • Review keywords before opening a rule.
  • Add a custom rule with a unique name, supported category, keywords, and priority.
  • Edit or delete rules you created.
  • Inspect built-in rules while keeping the shipped defaults intact.

Custom rules are stored locally and survive application updates. The editor validates names, priorities, required categories, and duplicate rules before saving.

Writing useful rules¶

Prefer evidence that is stable in downloaded statements:

  • Use a merchant token such as TRADER JOE instead of a city or card suffix.
  • Add only variants that belong to the same merchant and category.
  • Avoid broad words such as PAYMENT, STORE, or a state abbreviation.
  • Choose an existing category whenever possible so reporting stays consistent.

Suggested workflow¶

  1. Review Uncategorized transactions on the Transactions page.
  2. Confirm that the same description pattern appears more than once.
  3. Add a focused rule for that pattern.
  4. Go to Process and run again.
  5. Verify the result and stage on Transactions.

For a one-time exception, edit the transaction directly instead. Manual edits are recorded as user_defined and protected by default during later merges.
