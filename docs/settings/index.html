Settings¶

In FinAgent: Configuration Settings

Settings is where you tell FinAgent where your files live and which tools it may use while categorizing transactions. Everything is stored in a local config.json; there is no FinAgent account and no hosted settings service.

On a first launch, Settings also acts as the setup guide. Complete the required fields marked with *, then select Complete setup. FinAgent opens Import next.

First-run checklist¶

  1. Choose a statements folder and a processing folder.
  2. Enter the name FinAgent should use in greetings.
  3. Choose a Location Engine method.
  4. Choose an AI Engine provider, or select None.
  5. Confirm the dashboard port.
  6. Select Complete setup.

After setup, Import unlocks. Process unlocks when at least one supported statement is present, and the analysis pages unlock after a successful run.

State Pages available
Setup not complete Settings
Setup complete, no statements Settings, Import
Statements available, no processed data Settings, Import, Process
Processed dashboard data available All pages

Profile¶

The profile switch chooses between Personal and Dev settings. Personal is the normal, privacy-focused experience. Dev uses a separate config file and unlocks maintainer options such as Selenium-based Google Maps lookup and adding categories.

Switching to Dev requires the password shown by the application. The selected profile is only a preview until you select Save changes. Learn how the two configurations stay isolated in Profiles.

Folders¶

The two folders are selected during first-run setup:

  • Statements folder: stores imported bank CSV files and supported Bank of America tabular text exports. FinAgent creates bank and account-type subfolders as needed.
  • Processing folder: stores normalized transactions, categorized output, local caches, budgets, and the dashboard's persistent transaction data.

These paths are locked in the dashboard after setup. To move them safely, run:

finagent --reconfigure

In Docker, these paths are bind mounts and remain locked. Change them in the next docker_up.sh command when recreating the container. See Import for the statement filing workflow.

Identity¶

Your name is used for local greetings in FinAgent. It is never sent to a lookup service or model provider.

Dashboard¶

Port controls the local dashboard address and defaults to 3001. Native runs listen on 127.0.0.1, so the dashboard is available only on your machine. Documentation normally uses the dashboard port plus 2.

A port change is saved immediately but takes effect on the next launch. Follow Restarting FinAgent after changing it.

Location Engine for Categorization¶

The Location Engine runs after Rules and before the AI Engine. Choose one method:

  • Open Street Map: free Nominatim lookup; no API key required.
  • Place API: Google Places lookup for every unresolved merchant; billing-enabled API key required.
  • Place API combined flow: tries OpenStreetMap first and calls Google only when no useful category is found.
  • Off: sends no merchant description to a location service.
  • Google Maps and Combined: Dev-only Selenium methods that control a local Chrome browser.

The Advanced menu contains an optional OpenStreetMap contact email and, for Dev Selenium methods, a ChromeDriver path. Setup instructions, comparison guidance, Google Places key creation, privacy, and cost details are all in Location Engine.

AI Engine for Categorization¶

The AI Engine only receives transactions that Rules and the Location Engine did not resolve. Available providers are:

  • Ollama: local and free. Select a model already downloaded on this machine, or use Pull model in native mode.
  • OpenRouter: hosted API. Add an OpenRouter key and choose one of the listed models; complimentary models may be rate-limited.
  • Claude: hosted Anthropic API. Add a billed API key and choose a model.
  • None: use deterministic Rules and the optional Location Engine only.

Use the provider's Test button before processing. API keys are stored in your local config and returned to the dashboard only as masked values. Ollama keeps merchant descriptions local. Cloud models receive merchant descriptions, not transaction amounts or account numbers.

The Advanced menu contains:

  • Temperature: randomness of model output, from 0 to 2; default 0.1.
  • Max tokens: response limit for each model call; default 4096.

The defaults are designed for FinAgent's structured prompt. See AI Engine before changing them.

Save, discard, and apply¶

  • Save changes writes the displayed profile and activates it.
  • Discard reloads the active profile and removes unsaved edits.
  • Complete setup writes the initial configuration and opens Import.

Most provider and lookup changes are used on the next processing run. After saving, go to Process and run again. Port changes require a restart.

Configuration reference¶

Personal settings normally live at ~/.finagent/config.json; Dev settings normally live at ~/.finagent-dev/config.json. FINAGENT_CONFIG_DIR can supply a different directory for an advanced launch.

Key Values / default Purpose
user_name empty Local display name.
statements_dir ~/Documents/FinAgent/statements Raw imported statements; editable during setup or reconfiguration.
processing_dir ~/Documents/FinAgent/processing Processed output, caches, budgets, and dashboard data.
dashboard_port 3001 Dashboard port; documentation normally uses port + 2.
ui_profile personal or dev Profile recorded in this config.
llm_provider ollama, open_router, claude, or none AI categorization provider.
ollama_model qwen2.5:3b Ollama model tag.
ollama_api_url http://localhost:11434 Ollama server URL.
openrouter_api_key empty OpenRouter secret, masked in the dashboard.
openrouter_model inclusionai/ling-3.0-flash:free OpenRouter model.
claude_api_key empty Anthropic secret, masked in the dashboard.
claude_model claude-haiku-4-5 Claude model.
temperature 0.1 Model randomness, from 0 to 2.
max_tokens 4096 Maximum response tokens per model request.
location_lookup_method nominatim Active lookup method.
google_places_api_key empty Secret required for both Place API methods.
nominatim_email empty Optional contact email sent to OpenStreetMap.
google_maps_chromedriver_path empty Optional Dev-only Selenium driver path.
setup_complete false initially Set automatically after first-run setup.

Do not publish config.json: it can contain API keys and local folder paths. For command-line profile selection and one-run overrides, see Running from the Terminal.
