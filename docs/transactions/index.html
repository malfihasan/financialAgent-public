Transactions¶

In FinAgent: Primary navigation -> Transactions

Transactions shows the rows in FinAgent's persistent transaction master. Use it to search and filter activity, correct a category, or divide one purchase across several categories.

Review and edit¶

Search by description and use the month, institution, category, and categorization-stage filters to narrow the table. Selecting a new category marks that decision as user_defined, and normal processing runs preserve it.

The authoritative imported row remains in dashboard_data/master_transactions.csv. FinAgent identifies it with a stable transaction ID derived from its institution, account, date, description, and amount.

Split a transaction¶

Use the branch button on a transaction row to open Split transaction.

  1. Choose Amount or Percentage entry mode.
  2. Add at least two allocations.
  3. Select a category and enter a positive value for every allocation.
  4. Use Adjust beside a row to fill it with the exact amount or percentage remaining after the other rows.
  5. Select Save split.

FinAgent preserves the original debit or credit sign. Percentage mode is an entry convenience; saved allocations use currency amounts so totals remain exact to the cent.

Saved allocations appear as category tags on the parent row. Category filters also match those allocations. Open the split editor again to revise them, or select Remove split to restore the original category as the only category used by analytics.

Storage and analytics¶

Splits are stored separately in dashboard_data/transaction_splits.csv; FinAgent does not duplicate or rewrite the original row in master_transactions.csv. Dashboard and Budget analytics materialize the allocations when totaling categories, income, and spending. The parent still counts as one transaction, so splitting does not inflate transaction counts.

Normal processing preserves split metadata. A deliberate manual-category overwrite removes all existing splits before recalculation. See Process before enabling that option.

Budget mappings

If a mixed purchase belongs to several budget categories, split the actual transaction here. Budget-versus-actual totals then use those allocations automatically.
