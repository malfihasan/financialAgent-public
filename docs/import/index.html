Import¶

In FinAgent: Top-right toolbar -> Import statements

Import brings downloaded bank statements into FinAgent's statements folder. It does not process or categorize them yet; it validates the form, gives the file a consistent name, and places it in the correct bank/account folder for the next run.

Before importing, complete Settings. New users reach Import automatically after selecting Complete setup.

Use transaction exports, not PDFs

Download CSV, comma-separated, or a supported tabular text export from your bank. PDF statements are visual documents and are not supported. Bank of America checking .txt exports are converted automatically.

Supported institutions¶

Institution Account types Import folder
American Express Credit AMEX/CreditAC
Bank of America Checking, Credit BOA/CheckingAC or BOA/CreditAC
Chase Checking, Credit CHASE/CheckingAC or CHASE/CreditAC
Citi Credit CITI/CreditAC
US Bank Checking, Credit USBANK/CheckingAC or USBANK/CreditAC

Import a statement¶

  1. Export transactions from the bank website in a supported format.
  2. Select Import statements in the top-right dashboard tools.
  3. Choose the institution and account type.
  4. Enter the account's last four digits.
  5. Optionally enter an alphanumeric account label.
  6. Optionally enter both statement dates in YYYYMMDD format.
  7. Choose the downloaded file and select Import.

Repeat these steps for every statement you want included, then select Run processing to continue to Process.

Account status¶

Each linked account shows a Processed or Draft badge. Draft means the account's imported statement has not been found in your merged dashboard data yet; Processed means it has. This is a live check against the dashboard's merged transaction history each time the Import page loads, so the badge stays correct even if a manual reset or edit changes what's actually on the dashboard, not just what was clicked "Import" once. The date range shown under a Processed account reflects the earliest and latest transaction dates actually found for it, not the dates typed in during import.

Account labels¶

Labels make multiple accounts from the same institution easier to recognize. FinAgent remembers a label for the matching institution, account type, and last four digits. If the label is blank, it reuses a known match or creates a unique five-digit label.

Statement dates¶

Dates are optional, but supply both when using them. For example, January 1 through March 31, 2026 is 20260101 through 20260331.

When both fields are blank, FinAgent assigns a safe synthetic range beginning at 19000101. Later undated imports for that account continue after the previous synthetic end date so their filenames do not collide. These filename dates identify files; processing still reads transaction dates from the statement contents.

What FinAgent stores¶

An imported filename records the institution, account label, account type, last four digits, and date range. The original upload is copied into your configured statements directory; processing output stays in the separate processing directory.

FinAgent also stores reusable account metadata in statement_accounts.json inside the statements folder. This local file keeps labels and automatic date ranges consistent.

Importing by hand¶

Advanced users can place supported files directly into a matching folder such as <statements>/BOA/CheckingAC/. Use the same naming pattern as existing files so account and date metadata can be parsed reliably. The dashboard Import page is recommended because it validates and names the file for you.

Duplicate and corrected statements¶

Import does not delete earlier files. If a bank issues a corrected export, remove or archive the superseded statement from the statements folder before processing to avoid duplicate source rows.

When all files are ready, use Process. Platform-specific folder and permission notes are under Installation in the navigation.
