Installation¶

FinAgent ships as a standalone binary — no Python required for normal use. Pick your platform below. For commands only, see Quick start.

Docker installation¶

The Docker release contains the packaged FinAgent binary, dashboard, documentation, Node.js, and Ollama. It does not contain the private source tree or raw Python source files.

Docker requirements¶

  • Docker Desktop, or Docker Engine with Docker Compose.
  • FinAgent-Docker-x86_64.tar.gz, docker_up.sh, and docker-compose.yml from the same release, kept in one folder.
  • Two host folders: one for statements and one for processing output.

Load and start the image¶

  1. Load the release image and make the launcher executable:

    docker load -i FinAgent-Docker-x86_64.tar.gz
chmod +x docker_up.sh

  2. Start without downloading an LLM model:

    ./docker_up.sh \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing" \
   --no-ollama-model

  3. Open the dashboard at http://localhost:3001 and documentation at http://localhost:3003.

The launcher creates missing host folders. Settings displays mounted paths as Docker-locked so every component continues using the same persistent folders.

Preview before starting

Add --dry-run to print the Compose command, ports, mounts, provider, and model choice without opening a container.

Docker ports¶

The dashboard defaults to host port 3001. Documentation defaults to the dashboard port plus 2, so it normally uses 3003.

./docker_up.sh \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing" \
   --port 4100 \
   --docs-port 4200 \
   --no-ollama-model

Both ports must be different whole numbers from 1024 through 65535. The dashboard port must be 65533 or lower because FinAgent reserves its internal documentation port. Invalid values are rejected before Docker starts.

Ollama in Docker¶

Ollama is always installed in the image. Model downloads are optional and are stored in the persistent ollama-data volume.

# Pull and select the small default model: qwen2.5:0.5b
./docker_up.sh --ollama-model \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing"

# Pull and select another model
./docker_up.sh --ollama-model qwen2.5:3b \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing"

# Skip model download
./docker_up.sh --no-ollama-model \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing"

With neither model flag, an interactive terminal asks whether to download qwen2.5:0.5b; unattended runs do not prompt or download. An explicit model choice becomes the active model shown in Settings and overrides an older model in mounted config for that launch. A restart without an explicit provider or model preserves values previously saved in Settings.

Claude or OpenRouter in Docker¶

Cloud providers require no additional container software. Keep keys out of shell history by using a local permission-restricted environment file.

mkdir -p "$HOME/.config/finagent"
printf '%s\n' 'ANTHROPIC_API_KEY=your-key' > "$HOME/.config/finagent/docker.env"
chmod 600 "$HOME/.config/finagent/docker.env"

./docker_up.sh --llm-provider claude \
   --env-file "$HOME/.config/finagent/docker.env" \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing"

mkdir -p "$HOME/.config/finagent"
printf '%s\n' 'OPENROUTER_API_KEY=your-key' > "$HOME/.config/finagent/docker.env"
chmod 600 "$HOME/.config/finagent/docker.env"

./docker_up.sh --llm-provider open_router \
   --env-file "$HOME/.config/finagent/docker.env" \
   --statements "$HOME/Documents/FinAgent/statements" \
   --processing "$HOME/Documents/FinAgent/processing"

The env file accepts only ANTHROPIC_API_KEY and OPENROUTER_API_KEY. Keys are injected at startup, masked in the dashboard, and never copied into the image. Providers can also be changed in Settings → Categorization engine.

Docker data and persistence¶

Data Storage Persists after restart?
Imported statements Host --statements folder Yes
Processing and dashboard data Host --processing folder Yes
FinAgent settings Host --config folder (default .docker-config) Yes
Ollama models Docker volume ollama-data Yes

The container restarts automatically unless explicitly stopped.

Check, restart, and stop Docker¶

docker ps --filter name=finagent
docker logs finagent
curl http://localhost:3001/api/config

docker restart finagent
docker compose --project-name finagent down

Run ./docker_up.sh again to recreate a stopped container with the mounts, ports, and provider options you want.

Update the Docker release¶

  1. Download the new image archive and matching launcher files.
  2. Run docker compose --project-name finagent down.
  3. Run docker load -i FinAgent-Docker-x86_64.tar.gz.
  4. Start again with ./docker_up.sh and your normal options.

Mounted data, config, and the Ollama model volume remain available when the container is replaced.

Docker troubleshooting¶

  • Invalid port: choose different ports from 1024 through 65535; keep the dashboard port at 65533 or lower.
  • Cloud key missing: pass the provider key through --env-file or save it from Settings.
  • Ollama model unavailable: restart with --ollama-model or --ollama-model <name>.
  • Image not loaded: run docker load -i FinAgent-Docker-x86_64.tar.gz.
  • All launcher options: run ./docker_up.sh --help.

macOS installation¶

  1. Download the latest FinAgent-<version>-macOS.dmg from the GitHub releases page.

  2. Install: open the DMG and drag FinAgent.app into Applications.

  3. First launch — approve the security check. Development builds are not notarized with a paid Apple Developer ID, so macOS Gatekeeper may say Apple could not verify that FinAgent is free of malware and offer to move it to the Trash. Approval is needed once per install/update. Ad-hoc signing does not remove the warning for downloaded apps; avoiding it requires Apple notarization and a paid Apple Developer account. Use one of these approval methods:

    • Right-click (or Control-click) FinAgent.app → Open → Open.
    • If macOS still refuses ("Apple could not verify…"), go to System Settings → Privacy & Security, scroll to the Security section, and click "Open Anyway" next to the FinAgent message, then confirm with your password or Touch ID.
    • For a release downloaded from the official FinAgent Releases page that you trust, Terminal can remove the quarantine flag with xattr -dr com.apple.quarantine /Applications/FinAgent.app.

  4. Launch. Double-clicking FinAgent.app opens a Terminal window, starts the app, and opens your browser on the dashboard. First run walks you through setup.

The macOS app includes the dashboard runtime. You do not need to install Node.js or Python separately.

Set up the finagent terminal alias (macOS)¶

The docs and dashboard refer to the finagent command. The binary lives inside the app bundle, so add an alias to your shell profile:

# zsh (default on modern macOS)
echo 'alias finagent="/Applications/FinAgent.app/Contents/MacOS/finagent"' >> ~/.zshrc
source ~/.zshrc

# bash
echo 'alias finagent="/Applications/FinAgent.app/Contents/MacOS/finagent"' >> ~/.bash_profile
source ~/.bash_profile

Verify it works:

finagent --version

The wrapper at Contents/MacOS/finagent detects how it was invoked: from a shell it runs inline (all terminal flags work as expected); from Finder it opens Terminal.app for you.

Linux installation¶

  1. Install Node.js (required for the dashboard). FinAgent launches a Node.js server for the dashboard, so node must be on your PATH first:

    # Debian/Ubuntu — NodeSource LTS repo (gives a current version; the
# distro-packaged "nodejs" apt package is often too old)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# Fedora/RHEL
sudo dnf install -y nodejs

# Arch
sudo pacman -S nodejs npm

    Verify with node --version (v18+; v20 LTS recommended). 2. Download the Linux archive from the releases page and extract it:

    tar -xzf FinAgent-<version>-linux.tar.gz -C ~/finagent

  2. Make the command available on your PATH (pick one):

    # symlink (recommended)
sudo ln -s ~/finagent/finagent /usr/local/bin/finagent

# or shell alias
echo 'alias finagent="$HOME/finagent/finagent"' >> ~/.bashrc && source ~/.bashrc

  3. Run finagent — the dashboard opens in your default browser. If your distribution blocks the binary, mark it executable first: chmod +x ~/finagent/finagent.

Windows installation¶

  1. Download FinAgent-<version>-Windows-x64.exe from the releases page.
  2. Run the installer. It includes the dashboard runtime and creates Start Menu shortcuts; a desktop shortcut is optional. No separate Python or Node.js installation is required.
  3. If SmartScreen displays "Windows protected your PC", click More info → Run anyway.
  4. Leave Launch FinAgent selected on the final page. The browser opens to first-run setup. Later, use the Start Menu or desktop shortcut.

If installation fails unexpectedly, FinAgent writes a short, non-secret diagnostic file in the Windows temporary folder and opens a pre-filled GitHub issue for your review. It includes the FinAgent and Windows versions; attach the installer log only if a maintainer requests it.

Requirements¶

  • Linux only: Node.js 18+ on PATH (20 LTS recommended). macOS and Windows releases include the dashboard runtime; Docker includes all runtimes and Ollama.
  • A categorization engine is optional: Ollama, OpenRouter, Claude, or none for rules and location lookup only.
  • ~500 MB disk for the app plus processed data. Allow additional space for local Ollama models.

Setting up an LLM provider¶

FinAgent uses an LLM to categorize transactions its rule engine can't classify on its own. You choose the provider during first-run setup (or later on the Settings page / finagent --setup). Pick one of the three:

Option A — Ollama (local, free, private, recommended)¶

Runs entirely on your machine — transaction descriptions never leave your computer, and there's no API key or bill.

  1. Install Ollama:

    • macOS: download from ollama.com/download and drag it to Applications, or brew install ollama.
    • Windows: download the installer from ollama.com/download and run it. Ollama installs itself as a background service with a system-tray icon.

    • Linux:

      curl -fsSL https://ollama.com/install.sh | sh

    Ollama starts automatically after install and listens on http://localhost:11434. Verify with:

    ollama --version

  2. Pull a default model. FinAgent's built-in default is the small qwen2.5:3b, but the newer Qwen 3 family is a great free default — fast, accurate enough for categorization, and light on RAM:

    ollama pull qwen3

    On a machine with limited RAM (≤8 GB), use the smaller tag instead:

    ollama pull qwen3:4b

  3. Point FinAgent at the model. In FinAgent's Settings page, choose Ollama as the LLM backend and set the Ollama model field to the tag you pulled (e.g. qwen3 or qwen3:4b). From the terminal wizard, the same prompt is called "Ollama model name".

  4. Verify it works:

    ollama list          # confirms the model was downloaded
ollama run qwen3 "hi" # quick smoke test

Option B — OpenRouter (cloud API — free to get a key)¶

OpenRouter gives you access to many hosted models through one API. Creating an account and generating an API key costs nothing, and OpenRouter offers several :free-tagged models you can use at no charge (paid models are billed per-token only if you choose one later).

  1. Go to openrouter.ai and click Sign Up (GitHub, Google, or email — free).
  2. Once logged in, open openrouter.ai/keys.
  3. Click Create Key, give it a name (e.g. "FinAgent"), and click Create.
  4. Copy the key immediately — it's shown only once and starts with sk-or-....
  5. In FinAgent, choose OpenRouter as the LLM backend and paste the key into the OpenRouter API key field (Settings page, or the finagent --setup wizard).

Option C — Claude / Anthropic (cloud API — paid)¶

Anthropic's Claude models give the highest categorization accuracy but require a billed API key — unlike OpenRouter, there is no free tier.

  1. Go to console.anthropic.com and sign up or log in.
  2. Add billing (required before the API will work): open Settings → Billing, add a payment method, and purchase API credits. Anthropic bills per token — check current rates at anthropic.com/pricing before heavy use.
  3. Open API Keys in the console sidebar and click Create Key. Name it (e.g. "FinAgent") and create it.
  4. Copy the key immediately — it's shown only once and starts with sk-ant-....
  5. In FinAgent, choose Claude as the LLM backend and paste the key into the Claude API key field. The default model is claude-opus-4-5; you can change it in the same form.
