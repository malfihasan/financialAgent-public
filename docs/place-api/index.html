Google Places API lookup¶

FinAgent can resolve a merchant's category from Google Places — a paid, high-accuracy alternative to the free OpenStreetMap lookup. This page covers what it does, how the request flow works, and what it costs.

Where it fits in the pipeline¶

Every run resolves categories in this order:

rule engine  →  location lookup (this stage)  →  language model  →  merge

Location lookup itself has several interchangeable backends, selected by Settings → Location Engine for Categorization → Method. Google Places is one of them, alongside OpenStreetMap (Nominatim), Google Maps (Selenium, Dev only), and "off". Whichever merchants the location stage cannot resolve are passed on to the configured LLM.

The two Place API modes¶

Method What it does
place_api Calls Google Places for every merchant not already cached. Most accurate, calls Google most often.
place_api_combined Tries the free OpenStreetMap lookup first; only calls Google Places when OpenStreetMap has no usable category. Fewer paid calls.

Both modes are available in the Personal profile — no need to switch to Dev.

Getting an API key¶

  1. In Google Cloud Console, enable Places API (New) on a project with billing enabled.
  2. Create an API key and (recommended) restrict it to the Places API.
  3. Paste the key into Settings → Google Places API key. It's masked after saving; leave the masked value alone to keep the existing key.

Full walkthrough

See Google's own guide: Get a Places API key — also linked directly from the Settings field.

How a match is decided¶

Google Places results are matched conservatively rather than optimistically:

  • Only a fixed allowlist of specific Google place types (e.g. grocery_store, coffee_shop, gas_station) map to a FinAgent category. Broad types like store or point_of_interest are deliberately ignored — they're too vague to categorize safely.
  • The returned business name and the most specific location evidence available (an exact ZIP code, or a matching city/state) must agree with the statement text before a match is accepted.
  • Anything ambiguous, mismatched, or using an unmapped type is left uncategorized rather than guessed — it can still be picked up by the LLM stage or a manual rule.

Privacy and cost¶

  • FinAgent sends Google only the merchant query text and whatever location hint is available (ZIP, city, or state) — never transaction amounts, account numbers, or your name.
  • Requests run directly from your machine to Google; nothing is proxied through a FinAgent server.
  • Every resolved merchant is cached locally (each mode keeps its own cache), so the same merchant is only looked up once until the cache entry expires — this keeps repeat runs fast and avoids repeat billing.
  • Google Places is a paid API. Charges are billed by Google directly to the Google Cloud project tied to your key; FinAgent does not track or estimate your Google bill. Review Places API pricing before enabling it.
  • The Settings page flags this method with a 💵 "may cost money" badge next to the Location Engine section heading, so it's never a silent choice.

Configuration reference¶

Key Values Notes
location_lookup_method place_api · place_api_combined See Configuration reference for the full list of methods.
google_places_api_key string Required by both Place API modes. Stored locally in config.json and masked by the dashboard API.
