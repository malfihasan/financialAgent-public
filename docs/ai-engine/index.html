AI Engine¶

In FinAgent: Configuration Settings AI Engine for Categorization

The AI Engine is FinAgent's final categorization stage for transactions that Rules and the Location Engine could not resolve.

Rules -> Location Engine -> AI Engine -> Merge

It reads a merchant description, chooses from FinAgent's supported Categories, and returns a structured category. It does not calculate dashboard totals, modify raw statements, or replace protected manual choices.

Choose an option¶

Provider Runs where Internet Cost Setup
Ollama Your machine Not for categorization Free Install Ollama and pull a model
OpenRouter Hosted API Required Complimentary or paid model-dependent usage Create an API key
Claude Anthropic API Required Paid token usage Add billing and create an API key
None Disabled No Free No installation

Choose Ollama when privacy and offline processing matter most. Choose OpenRouter for hosted models with a complimentary starting option. Choose Claude when you prefer Anthropic's models and accept paid API usage. Choose None for deterministic Rules and optional Location Engine only.

Ollama: local and private¶

Ollama runs models on your computer, so transaction descriptions do not leave the machine during AI categorization. Performance depends on available memory, CPU, and GPU resources.

Install Ollama¶

Download the app from ollama.com/download, or install it with Homebrew:

brew install ollama

Open the Ollama app, or start the service with ollama serve.

Download and run the Windows installer from ollama.com/download. Ollama normally starts as a background service after installation.

curl -fsSL https://ollama.com/install.sh | sh

If the service is not already running, start it with ollama serve.

Ollama is included in the FinAgent Docker image. Pull the small Docker default during startup:

./docker_up.sh --ollama-model \
  --statements "$HOME/Documents/FinAgent/statements" \
  --processing "$HOME/Documents/FinAgent/processing"

Supply a model name after --ollama-model to choose another one.

Pull and select a model¶

For a native installation, pull a model before processing:

ollama pull qwen2.5:3b
ollama list

Then open Settings -> AI Engine for Categorization, choose Ollama, select the downloaded model, and use Test Ollama.

FinAgent's configured default is qwen2.5:3b. The Settings list also supports:

Model Practical use
qwen2.5:0.5b Smallest option; useful on limited hardware or for quick tests
qwen2.5:3b Balanced FinAgent default
qwen2.5:7b Larger model with higher memory use
llama3.2:3b Alternative compact general model
mistral:7b Larger alternative with higher memory use
phi3:mini Compact alternative

The dashboard can pull a missing model on native installations. Docker models must be selected with docker_up.sh --ollama-model [NAME] and persist in the ollama-data volume.

OpenRouter: hosted model access¶

OpenRouter requires no local model installation. It sends unresolved merchant descriptions to the selected hosted model.

Set up OpenRouter¶

  1. Create an account at openrouter.ai.
  2. Open openrouter.ai/keys.
  3. Create a key and copy it when shown.
  4. In Settings -> AI Engine for Categorization, choose OpenRouter.
  5. Paste the key, select a model, save, and use Test OpenRouter key.

FinAgent currently offers these Settings choices:

Model Notes
inclusionai/ling-3.0-flash:free Default complimentary option
nvidia/nemotron-3-ultra-550b-a55b:free Complimentary large-model option
nvidia/nemotron-3.5-lightning:free Complimentary speed-focused option

Complimentary models may be rate-limited, renamed, or temporarily unavailable by OpenRouter. Review the provider's model page before relying on one for an automated workflow.

Claude: Anthropic API¶

Claude requires no local model installation, but Anthropic API access is paid. FinAgent reports an estimated output-token cost after processing; the provider's billing page remains authoritative.

Set up Claude¶

  1. Create or open an account at console.anthropic.com.
  2. Add billing or API credits.
  3. Open API Keys, create a key, and copy it when shown.
  4. In Settings -> AI Engine for Categorization, choose Claude.
  5. Paste the key, select a model, save, and use Test Claude key.

Available Settings choices are:

Model Notes
claude-haiku-4-5 Default; faster and lower cost
claude-opus-4-5 Most capable option; higher cost

None: deterministic processing¶

Choose None - rules and location only when no AI provider should run. No AI software, model download, key, internet connection, or token billing is needed. Rules and the selected Location Engine continue to categorize transactions.

What cloud providers receive¶

The AI Engine supplies the transaction description and the category vocabulary needed by the prompt. Cloud requests do not include transaction amounts, account numbers, raw statement files, or your display name. Transactions already resolved by Rules or the Location Engine normally skip this stage.

API keys are stored in your local profile configuration and returned to the dashboard only as masked values. Do not publish config.json or paste keys into commands that shell history may save.

Advanced settings¶

The Advanced control in Settings exposes:

  • Temperature (0.1 by default): lower values make choices more repeatable.
  • Max tokens (4096 by default): limits each response.

The defaults are tuned for short, structured categorization output. Change them only when a selected model consistently fails to return a valid category.

Cache and one-run controls¶

Repeated descriptions can use the active model's local cache. Advanced terminal commands can rebuild it or change the provider for one run:

finagent --clear-llm-cache --llm-provider ollama --orgs boa
finagent --refresh-llm-cache --llm-provider open_router --orgs boa
finagent --no-llm --orgs boa

See Running from the Terminal for every provider, cache, and batch option.

Protect and improve results¶

Before a dashboard processing run, FinAgent asks whether prior manual, Location Engine, and AI Engine categories may be overwritten. Keep protections enabled when existing decisions should win.

Review AI results on Transactions. Correct a one-time exception manually, or create a deterministic Rule for a merchant you expect to see again. That rule will run before both engines on future imports.

Troubleshooting¶

  • Ollama not reachable: open the Ollama app or run ollama serve, then use Re-check in Settings.
  • Ollama model missing: run ollama pull <model> or use the dashboard's native Pull model action.
  • OpenRouter or Claude test fails: verify the key, selected model, internet access, provider balance, and rate limits.
  • No AI categories appear: confirm the provider is not None and remember that Rules and Location Engine matches intentionally skip AI processing.
