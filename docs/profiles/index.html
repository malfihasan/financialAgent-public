Profiles¶

In FinAgent: Configuration Settings Profile selector

Profiles keep everyday personal settings separate from development and testing settings. The active profile appears in the dashboard header.

Personal¶

Personal is the default and the right choice for normal use.

  • Uses ~/.finagent/config.json by default.
  • Offers OpenStreetMap, Google Places, Google Places combined flow, or Off for the Location Engine.
  • Supports Ollama, OpenRouter, Claude, or no AI Engine.
  • Keeps Selenium maintenance options hidden.
  • Prevents adding categories outside the shipped vocabulary.

Dev¶

Dev is intended for maintainers and controlled experiments.

  • Uses ~/.finagent-dev/config.json by default.
  • Keeps its own folders, provider, keys, lookup method, and dashboard settings.
  • Adds Google Maps Selenium and OpenStreetMap/Selenium Combined lookup.
  • Exposes an optional ChromeDriver path.
  • Allows adding custom categories, although using the built-in set is still recommended.

Switch in Settings¶

  1. Open Configuration -> Settings.
  2. Select Dev and enter the application password (finagent), or select Personal to return.
  3. Review the newly displayed profile's values and config path.
  4. Select Save changes to activate it.

Changing the toggle previews the other profile; it does not activate that profile until save. Discard returns to the currently active profile. Processing always uses the active profile.

Read Settings for every configuration section and required field.

Start with a profile from the terminal¶

finagent --profile personal
finagent --profile dev

Without --profile, FinAgent starts Personal. The profile flag is consumed before configuration loads, so it also works with processing and maintenance commands:

finagent --profile dev --orgs boa
finagent --profile personal --dashboard-only

Custom development paths¶

The development helper dashboard/restart-server.sh accepts profile and config path overrides. When it starts with --profile and --config-dir, that custom config directory remains attached to the starting profile while the server is running. The other profile keeps its normal config path.

An explicit --data-dir is pinned for that development launch. Without it, activating a profile also changes statements and processing paths to those in the selected profile.

For all launch flags, see Running from the Terminal.
