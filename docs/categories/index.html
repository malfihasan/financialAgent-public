Categories¶

In FinAgent: Configuration Categories

FinAgent uses a two-level category vocabulary written as group:subcategory, for example food:groceries or housing:rent_mortgage. The dashboard displays friendly labels and emojis, while the stable value keeps rules, lookup results, model prompts, budgets, and historical data aligned.

How categorization works¶

Every processing stage chooses from the same vocabulary:

  1. Rules apply deterministic merchant keywords.
  2. The Location Engine maps supported business types.
  3. The optional AI Engine selects from the remaining valid categories.
  4. A manual edit on Transactions records your choice as user_defined.

The Transactions page shows how each result was assigned. Categories left unresolved remain uncategorized instead of being forced into a weak match.

Browse available categories¶

Open Configuration -> Categories in the dashboard. The page groups all built-in values by their top-level group and provides the exact identifiers used by Rules and processing. Use search to find the closest supported option before creating a new one.

The shipped vocabulary covers income, housing, food, transport, shopping, health, financial activity, transfers, entertainment, travel, charity, and other common personal-finance activity. The application itself is the current reference list, so it stays synchronized with the installed release.

Adding a category¶

Adding categories is intentionally limited to the Dev profile. The built-in set is tuned across rules, lookup mappings, model prompts, analytics, and budget matching; unnecessary additions fragment reporting history.

When a genuinely new category is needed:

  • Choose an existing top-level group.
  • Enter a subcategory; FinAgent converts it to lower_snake_case.
  • Optionally choose an emoji for dashboard display.
  • Save it, then update the relevant rule or transaction.

A newly added category applies to future choices and processing. It does not silently rewrite old transactions. Reprocess deliberately if historical rows should use it.

Manual corrections¶

Use the edit action on the Transactions page to change one row. FinAgent marks the result user_defined; normal processing protects that choice during the merge. For a repeated merchant pattern, create a Rule instead so future imports receive the same category automatically.
