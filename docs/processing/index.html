Process¶

In FinAgent: Top-right toolbar -> Process statements

Process runs the complete FinAgent workflow and refreshes dashboard data. It starts with the statements collected by Import, applies the tools selected in Settings, and merges the result into one persistent transaction master.

Before a run¶

Confirm that:

  • Setup is complete and at least one supported statement is present.
  • The Settings page shows the model and location method you intend to use.
  • Any required local service, such as Ollama, is running.
  • Cloud API keys have passed the Settings test when using a cloud provider.

Select Process statements in the top-right dashboard tools.

Run from the dashboard¶

  1. Review Run defaults. These show the active Location Engine and AI Engine.
  2. Leave the date fields blank to process all available statement data, or choose an inclusive From and To range.
  3. Review the merge protection options.
  4. Select Run processing.
  5. Watch overall progress and the location/model sub-progress bars. Expand the run log for detailed output.
  6. When the run completes, return to Overview or Transactions to review it.

The date picker is not limited to the range from a previous run. A selected range controls the run and dashboard view without deleting older rows from the persistent transaction master.

Merge protection¶

FinAgent carries existing categorized rows into a normal refresh. Before a run, you can independently allow replacement of:

  • Manual categories (user_defined)
  • AI model categories (llm:<provider>)
  • Location categories (location_lookup)

Leave a protection off when those prior choices should win. Enable an overwrite only when you deliberately want that stage recalculated. Rebuilding with --overwrite-dashboard-data is a separate terminal maintenance operation that replaces the dashboard master from current pipeline output.

Transaction splits are treated as manual decisions. Normal runs preserve their separate split records. Enabling Manual categories overwrite deliberately removes existing splits so stale allocations cannot be applied to newly recalculated transactions.

Processing stages¶

1. Discover and parse statements¶

FinAgent scans the configured institution/account folders, identifies supported exports, and converts each bank's columns into a common transaction shape. Bank of America tabular checking exports are converted as part of import.

2. Normalize transactions¶

Dates, descriptions, signs, account metadata, and duplicate evidence are normalized. Optional organization and date filters are applied for the run.

3. Apply Rules¶

The deterministic Rules engine checks transaction descriptions first. Rule matches are fast, repeatable, and marked with stage rule.

4. Run the Location Engine¶

Unresolved merchants go to the configured Location Engine method. Accepted results are marked location_lookup; uncertain results move on without a forced category.

5. Run the AI Engine¶

Still-unresolved transactions go to the selected AI Engine. Ollama runs locally; OpenRouter and Claude use their APIs. Results record the provider, for example llm:ollama or llm:claude.

6. Merge protected decisions¶

FinAgent compares the new output with the dashboard's persistent master and preserves prior manual, model, and location decisions according to the run's merge choices. Carried rows may use the merge stage.

7. Publish dashboard data¶

The latest authoritative transactions are merged into dashboard_data/master_transactions.csv. Dashboard summaries are calculated from that master, the separate transaction_splits.csv metadata, and the selected inclusive view range. Refresh the browser if a completed run is not immediately visible.

Categorization stages in the dashboard¶

Stage Meaning
rule A deterministic keyword rule matched.
location_lookup A configured map/location resolver supplied the category.
llm:<provider> The selected model supplied the category.
user_defined You edited the category on Transactions.
merge A protected value was carried from an earlier run.
uncategorized No stage had enough evidence.

Progress, logs, and cost¶

The page shows overall progress plus dedicated location and model progress. The collapsible log is the best place to identify the current institution, stage, or error. For Claude runs, FinAgent reports observed output tokens and an estimated USD cost; Anthropic billing remains authoritative.

When a run does not complete¶

  • No statements: return to Import.
  • No transactions produced: verify statement format and selected dates.
  • Lookup failures: confirm internet access and the selected method; cached or unresolved merchants can still continue to later stages.
  • Model failures: use the provider test in Settings and verify the selected model or API key.
  • Wrong category preserved: rerun with the relevant merge overwrite enabled, or correct the row manually.

Advanced organization filters, cache maintenance, non-interactive runs, and master-data maintenance are documented in Running from the Terminal.
